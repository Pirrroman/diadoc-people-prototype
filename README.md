# Документы клиентам — прототип 0.1

Работающий статический прототип ЭДО с физлицами. Кабинет компании и мобильная страница получателя. Подготовлен для публикации в GitHub Pages из ветки main, папки /docs. n8n, серверная часть и ключи API не нужны.

## Быстро попробовать локально

Установите Node.js 20 или новее, откройте терминал в этой папке и выполните:

```sh
npm start
```

Откройте http://localhost:4173. Установка npm-пакетов и сборка не требуются. Не открывайте index.html двойным кликом: модули и загрузка примеров требуют HTTP/HTTPS.

Если Node.js отсутствует, из корня проекта можно запустить:

```sh
python -m http.server 4173 --directory docs
```

## Опубликовать в GitHub Pages

1. Создайте репозиторий, например `diadoc-people-prototype`. Для простого бесплатного размещения используйте публичный репозиторий; в нём будут только исходники и вымышленные примеры.
2. Загрузите содержимое этого проекта в корень репозитория. На верхнем уровне должны быть README.md, package.json и папка docs/, а не ещё одна внешняя папка архива.
3. Откройте **Settings → Pages**.
4. В **Build and deployment → Source** выберите **Deploy from a branch**.
5. В **Branch** выберите **main**, папку **/docs** и нажмите **Save**.
6. Дождитесь адреса, который покажет GitHub. Для репозитория из примера это будет `https://ВАШ-ЛОГИН.github.io/diadoc-people-prototype/`.

Файл docs/.nojekyll отключает обработку Jekyll. Если загрузка через веб-интерфейс его пропустила, создайте пустой файл с этим именем в папке docs/. Никаких переменных окружения, ключей СМС или дополнительных действий сборки не нужно. При публикации из корня вместо /docs сайт не запустится: index.html расположен в docs/.

Все пути относительные, маршруты находятся после #, поэтому название репозитория можно менять без исправления кода. Загрузка PDF в приложении не добавляет файл в репозиторий: он сохраняется только в браузере.

Официальные инструкции GitHub: [о Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages), [выбор ветки и папки](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site).

## Сквозной сценарий проверки

1. Нажмите **Новый документ → Использовать пример документа**. При желании загрузите свой тестовый PDF до 10 МБ.
2. Укажите вымышленные ФИО и телефон, сохраните черновик.
3. Проверьте PDF и нажмите **Создать приглашение**.
4. Нажмите **Открыть как клиент**. Можно открыть скопированную ссылку во второй вкладке того же браузера и профиля.
5. Получите тестовый код. Он показывается в блоке «Демонстрационное СМС». Введите его.
6. Прочитайте документ, отметьте условия и запросите второй код.
7. Подпишите в демо. Скачайте исходный PDF и отдельную демоквитанцию JSON.
8. Вернитесь в кабинет: статус и история обновились. После перезагрузки они сохраняются.

Для проверки отказа создайте ещё один документ и откажитесь со стороны получателя. Для проверки отзыва оставьте клиентскую вкладку открытой, отзовите документ в компании и вернитесь в клиентскую вкладку.

В разделе **Результаты проверки** считаются только новые документы; начальные примеры исключены. «Записать отказ» означает отдельный случай отказа до отправки, а не ещё одну запись для уже существующего документа. CSV не содержит имён, телефонов, кодов или содержимого документов.

## Что реализовано

- Два примера организаций; список, фильтры и поиск документов.
- Загрузка и локальное хранение PDF, контрольная сумма SHA-256, черновики и редактирование данных до отправки.
- Приглашение на 72 часа, отдельные тестовые коды доступа и подписания (5 минут, максимум 5 попыток, 30 секунд между повторами одного назначения).
- Подписание, отказ и отзыв, фиксация версии и правил, история действий.
- Повторное нажатие не создаёт второй результат подписания.
- Скачивание исходного PDF и отдельной демонстрационной квитанции.
- Локальные показатели, отметка помощи сотрудника и отдельный учёт отказа до отправки.
- Адаптивный интерфейс, клавиатурные действия, понятные ошибки и пустые состояния.
- Работа без внешних скриптов, шрифтов, аналитики и CDN.

## Ограничения этой версии

- **Только вымышленные данные.** Это демонстрация, не сервис для настоящих документов и не юридически значимое подписание.
- **Нет настоящей авторизации.** Переключение организаций иллюстрирует интерфейс. Все данные доступны владельцу браузера и могут быть изменены через инструменты разработчика.
- **Коды демонстрационные.** Они хранятся в браузере и видны на странице. Настоящая проверка телефона отсутствует.
- **Нет обмена между устройствами.** Документ существует только в том же браузере, профиле и адресе сайта. Новый браузер увидит свои примеры. Ссылка на загруженный документ из другого браузера покажет понятное сообщение о недоступности.
- **Нет синхронизации и резервных копий.** Очистка данных сайта удалит документы. Перенос с localhost на GitHub Pages создаёт новое хранилище.
- **PDF не модифицируется.** «Подписан · демо» — локальный статус. JSON-квитанция не является электронной подписью. У начальных примеров документ демонстрационный и не персонализирован под строку списка.
- **Нет интеграции с Диадоком и реальными СМС.** Следующая версия потребует отдельного сервера, даже если интерфейс продолжит размещаться на GitHub Pages.
- **Просмотр PDF зависит от браузера.** Всегда доступна кнопка открытия файла; на телефоне может использоваться встроенное приложение просмотра.
- **Сроки и права проверяются клиентом.** Изменение часов/кода/IndexedDB может обойти их. Это не механизм безопасности промышленного решения.
- **Несохранённая форма не восстанавливается.** Сохраните черновик перед уходом со страницы. Лимит размера PDF не заменяет проверку вредоносного содержимого на сервере.

## Структура

- `docs/index.html`, `docs/styles.css`, `docs/app.js` — интерфейсы и маршруты.
- `docs/domain.js` — состояния, проверки и расчёт показателей.
- `docs/storage.js` — IndexedDB, транзакции и загрузка примеров.
- `docs/assets/` — локальные PDF и шрифты.
- `tests/domain.test.mjs` — проверки важных правил.
- `scripts/serve.mjs` — локальный сервер для разработки, не нужен GitHub Pages.
- `PRODUCT.md`, `DESIGN.md`, `AGENTS.md` — контекст для дальнейшей разработки через Codex или Claude Code.

## Проверки

```sh
npm test
npm run check
```

При переходе к пилоту недостаточно добавить только отправку СМС. Нужны серверные права, неизменяемые версии, надёжное хранение доказательств, согласованная идентификация и подпись обеих сторон, эксплуатация и обработка ошибок. Браузерные модули хранения и подтверждений тогда заменяются серверным API.
